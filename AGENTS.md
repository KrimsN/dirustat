# AGENTS.md: руководство для ИИ-агентов и контрибьюторов

diRUSTat — open-source, нативный анализатор дискового пространства в духе WinDirStat и WizTree, написанный на **чистом Rust** (без JavaScript/TypeScript). **Без Tauri, Electron и webview-оболочек**: десктоп — нативный egui/eframe на wgpu. Цель: паритет с WinDirStat по функциям, скорость уровня WizTree (чтение NTFS MFT) и каждая функция доступна агентам. Разработкой занимаются агенты (Claude Code, Codex и др.) — этот файл их главная точка входа. Читай его целиком, затем `plan/STATUS.md`.

Название продукта в пользовательском тексте (UI, заголовки окон, About, инсталляторы, релизы, проза документации) всегда пишется **diRUSTat**. Машинные имена — строчные: крейты `dirustat-*`, бинарники `dirustat`/`dirustat-cli`, id `dev.dirustat.app`.

Стиль подхода заимствован у [storytold](https://github.com/storytold) (photocraft, wordcraft, craft-libs): слои с проверкой в xtask, «всё — команда», управление приложением через control-канал/MCP, жёсткий never-crash, живые документы прогресса и dev log для передачи работы между агентами.

## 0. Язык

| По-русски | По-английски |
|---|---|
| Ответы пользователю, документация (`*.md`), планы, задачи, комментарии в коде (`//`, `///`, `//!`), тексты ошибок и логов для людей | Идентификаторы (переменные, функции, типы, крейты, ключи, id команд), имена файлов и путей, ветки git, сообщения коммитов, внутренние рассуждения |

Технические термины не переводим (MFT, treemap, arena, backpressure) и пишем латиницей внутри русского текста. Подробности: `~/.claude/rules/language.md` у владельца; сообщения коммитов короткие английские в повелительном наклонении (`Add squarified layout`).

## 2. Карта workspace

```text
crates/
  model  treemap  ntfs     L0 фундамент: arena-дерево файлов, squarified-раскладка, разбор NTFS MFT
  scan                     L1 обход ФС -> model::Tree (переносимый + быстрый путь через ntfs)
  engine                   L2 Session + реестр команд (каждое действие — команда)
  control                  L3 control-канал (JSON/TCP) и MCP-сервер
  ui                       L4 egui-оболочка (тонкая, всё через engine)
apps/
  dirustat                 десктопное приложение (eframe/wgpu)
  dirustat-cli             headless CLI: scan / info / run / commands / mcp
xtask/                     cargo xtask layers | ci | (parity | perf | scorecard | fixtures — по мере появления)
```

**Слои проверяются** `cargo xtask layers`. Крейт зависит только от нижних слоёв. Ничего ниже `ui` не знает про egui/eframe/winit/rfd/wgpu; `dirustat-cli` не зависит от `ui`. Новый крейт регистрируется в `xtask/src/layers.rs`.

## 3. Золотые правила

### Never crash (приоритет выше фич)

Пользователь доверяет приложению свои диски; падение при сканировании или удалении недопустимо. Битая MFT-запись, имя файла с невалидным UTF-16, путь длиной 32k, исчезнувший посреди обхода каталог, отказ в доступе, переполнение размеров, враждебные параметры команды — всё это даёт **ошибку, которую можно обработать, а не панику**. Подробно: `docs/never-crash.md`.

- **Код вне тестов не паникует.** Никаких `unwrap()`, `expect()`, `panic!`, `unreachable!`, `todo!`, `unimplemented!`, индексации `[i]`/`[a..b]` (lints `deny` в workspace). Возвращай ошибку крейта и пробрасывай `?`; `ok_or(..)?`, `let .. else`, `get()`. Единственное исключение — доказуемо безотказный литерал: `#[allow(clippy::expect_used)]` + `.expect("почему не упадёт")`.
- **`unsafe` запрещён** (`unsafe_code = "forbid"` в workspace). Единственное исключение — изолированный крейт `dirustat-ntfs` (Win32 FFI для чтения тома, ADR 0002): `unsafe_code = "deny"`, каждый блок с `// SAFETY:`, `undocumented_unsafe_blocks = "deny"`, парсинг записей — safe-код + fuzz. Больше нигде `unsafe` не добавлять.
- **Числа из ФС и MFT враждебны.** Размеры, длины, смещения, счётчики записей — через `checked_*`/`saturating_*`, `try_from` вместо `as`, ограничение аллокаций размером входа, защита от деления на ноль и NaN/inf. Размеры дерева суммируются насыщающе.
- **Рекурсию ограничивай** (глубина, seen-set): каталоги бывают циклическими (junction, bind-mount, hardlink-каталоги). Обход дерева — итеративный.
- **Не каскадь.** Отравленные мьютексы обрабатывай (`lock().unwrap_or_else(PoisonError::into_inner)`), `join` потоков — это `Result`. Одна нечитаемая папка не обрывает скан: она помечается ошибкой и обход идёт дальше.
- **Последний рубеж.** Оболочка ловит панику вокруг диспетча команд и скана, сообщает как ошибку и сохраняет сессию. Это страховка, не разрешение паниковать. Держи `panic = "unwind"`.
- **Докажи.** Каждое исправление падения — с минимальным регрессионным тестом, который падал до фикса.

### Остальные правила

1. **Всё — команда.** Новое пользовательское поведение = команда в `engine` с id, подписью, пунктом меню, шорткатом, описанием параметров, `enabled` и `run`, плюс тесты. UI, CLI, control и MCP вызывают команды по id. Чисто визуальное состояние (масштаб, панели, раскладка) — в оболочке (`ui::UI_COMMANDS`). Программный вызов команды **никогда** не открывает диалог. Чеклист — `docs/contributing.md`.
2. **Только чтение по умолчанию.** Сканирование ничего не меняет на диске. Деструктивные команды (удаление, перемещение) — см. `docs/safety.md`: явный параметр подтверждения, по умолчанию в корзину, dry-run, и **агентам запрещено выполнять их на реальных данных пользователя** — только на временных фикстурах.
3. **Размер на диске ≠ размер файла.** Модель различает logical size и allocated size (кластеры, sparse, сжатие NTFS, hardlinks не считаются дважды, reparse points не обходятся). Не подменяй одно другим молча; режим показа — настройка.
4. **Clean-room.** WinDirStat (GPL) и WizTree (проприетарный) изучаются по поведению, публичной документации и наблюдению. **Никогда не копируй их код, иконки, строки локализации, ресурсы.** Особенно: WinDirStat под GPL — не читать его исходники для переноса логики. Алгоритмы берём из статей (squarified treemaps, cushion treemaps van Wijk) и публичных спецификаций NTFS. Сторонние ассеты — только с совместимой лицензией, файл лицензии рядом, строка в `ATTRIBUTION.md` в том же изменении. Шрифты в репозиторий не коммитим. См. `docs/clean-room.md`.
5. **Тесты — это гейт.** Каждое изменение с тестами. Обходы — на синтетических деревьях в `tempfile`-каталогах; парсеры — round-trip, property и fuzz; раскладка — инварианты (сумма площадей, отсутствие пересечений, пропорциональность).
6. **UI тонкий и data-driven.** Состояние UI сериализуется (serde), чтобы control-канал мог его читать и менять. Цвета и радиусы — из `theme::Tokens`, не хардкодом.
7. **Проверяй UI глазами.** Рендер offscreen/скриншот через control (`ui.screenshot`) и посмотри PNG. Демо-данные — синтетические; не используй содержимое реального диска пользователя в скриншотах и фикстурах.
8. **Производительность — фича.** Горячие пути измеряй в release на деревьях 1M+ узлов; бюджеты в `perf/budgets.toml`. Не сканируй и не пересчитывай всё дерево на каждый кадр — кэш по ревизии. Параллелизм — rayon/каналы; UI-поток не блокируется.
9. **Не ломай wasm для L0.** `model` и `treemap` обязаны проходить `cargo check --target wasm32-unknown-unknown` (чистые данные/геометрия, пригодны для web-демо). Остальное — десктоп.
10. **Зависимости — по минимуму.** Новая зависимость = строка в `docs/engineering.md` › Зависимости (зачем, лицензия, альтернатива) и проходит `cargo deny check`. Запрещены tauri/wry/electron/webview.

## 4. Как выбирать работу

Приоритет: важная инфраструктура → дешёвый паритет → длинный хвост.

0. Прочитай `plan/STATUS.md`, затем `docs/roadmap.md` › **Current focus**.
1. `docs/gaps.md` — ранжированный список. Бери верхнюю незаблокированную задачу вехи из STATUS.
2. `docs/target-app-parity.md` — матрица функций WinDirStat/WizTree; закрывая пункт, обнови строку (статус, дата) и пересчитай числа.
3. `log/devlog.md` — раздел «Still open» свежих записей.
4. Когда сделанное двигает число или закрывает gap — обнови соответствующие документы, поправь строку статуса и историю ревизий (`docs/progress-docs.md`).

## 5. Перед завершением задачи

```sh
cargo fmt --all
cargo clippy -p <затронутые крейты> --all-targets -- -D warnings
cargo test -p <затронутые крейты>
cargo xtask layers
cargo xtask ci                  # полный гейт: fmt, clippy, test, layers, wasm-core
```

Затем допиши краткую запись в `log/devlog.md` (что вошло, числа, что ещё открыто) и обнови `plan/STATUS.md`. Сессии обрываются (лимиты контекста, сбои) — dev log и зелёное дерево позволяют следующему агенту продолжить. **Дерево должно собираться на каждом шаге.** Коммить после каждой законченной дуги работы с id задачи (`M1.3: add scan progress channel`).

## 6. Параллельные агенты

- Свой target-каталог: `CARGO_TARGET_DIR=target/agent-<имя>` (избегает блокировки Cargo). Правь только файлы, которыми владеешь. Каталог ~несколько ГБ — удаляй `target/agent-*` завершённых агентов.
- Общие файлы (`engine/src/lib.rs`, список `specs()` в реестре команд, `ui/src/menus.rs`, `state.rs`) — маленькие точечные правки; перечитывай перед правкой.
- Новые команды — в **новом модуле** (`engine/src/cmd/<area>.rs` с функцией `specs()`), а не в разросшемся общем файле.
- Если чужая незавершённая правка ломает сборку — подожди и повтори, чужие файлы не чини.
- Манифесты `Cargo.toml` всегда валидны: glob `crates/*` означает, что один битый манифест ломает всех. Создавай/переписывай манифест атомарно: пиши во временный файл вне `crates/`, затем перемещай.
- Git: у каждого агента своя ветка/worktree (`agent/<имя>/<задача>`); в `main` — через PR/ревью. Не делай `git push --force`, `reset --hard`, не переписывай чужие коммиты.

## 7. Что решает человек (спрашивай, не угадывай)

Лицензирование и публикация (crates.io, GitHub, релизы), секреты и подпись, добавление новых зависимостей с копилефт-лицензией, изменение публичного протокола control после релиза, любое действие над реальными данными пользователя. Остальное решай сам и записывай решения в ADR/devlog. Подробнее — `plan/execution-plan.md` › Протокол.

## 8. Где что отслеживается

- `plan/STATUS.md` — текущее состояние для передачи между сессиями (обновляй в конце каждой).
- `plan/execution-plan.md` — детальный план вех и задач (M1.1, M1.2, …).
- `docs/roadmap.md` — вехи и текущий фокус; `ROADMAP.md` — одностраничная сводка с цифрами.
- `docs/target-app-parity.md`, `docs/gaps.md` — где мы относительно WinDirStat/WizTree.
- `docs/adr/` — решения; `log/devlog.md` — журнал.
- `perf/budgets.toml` — бюджеты производительности.
