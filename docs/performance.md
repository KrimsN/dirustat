# Производительность

> Статус: 2026-10-13 · ревизия 1. Бюджеты — в `perf/budgets.toml`; пока `enforce = false`, потому что замеров нет.

## Цели

| Сценарий | Бюджет | Комментарий |
|---|---|---|
| Скан 1M файлов, MFT (NTFS, админ) | ≤ 3 с | ориентир — WizTree |
| Скан 1M файлов, переносимый, SSD | ≤ 25 с | параллельный `read_dir`, rayon |
| Раскладка treemap, 1M узлов | ≤ 150 мс | lazy: раскладываем только видимые уровни по пикселям |
| Кадр treemap, 1M узлов | ≤ 8 мс | без раскладки на кадр, кэш по ревизии |
| Первая отрисовка после старта скана | ≤ 300 мс | UI отзывчив во время скана |
| Память | ≤ ~100 байт/узел (+ имя) | компактный `Node`, без лишних `String` |

## Как измерять

- Только `--release`. Эталонные деревья: генератор `cargo xtask fixtures` (детерминированный по seed) на 100k / 1M / 5M узлов; для MFT — отдельная ручная процедура на тестовом NTFS-томе (виртуальный диск VHDX с синтетическими данными).
- `cargo xtask perf --quick` — быстрый срез; `cargo xtask perf --update-baseline` — публикует полный прогон в `perf/baseline.json`.
- Записывай до/после в `log/devlog.md` (числа, машина, конфигурация).
- Когда бюджет выполнен — поставь `enforce = true` в `perf/budgets.toml`, чтобы CI ловил регресс.

## Горячие пути и приёмы

1. **Скан:** минимизировать системные вызовы на файл (получать размер вместе с `read_dir`: `FindFirstFileExW` с `FIND_FIRST_EX_LARGE_FETCH` на Windows), пакетные записи в arena, отсутствие блокировок на горячем пути (локальные буферы на поток, слияние в конце).
2. **MFT:** последовательное чтение крупными блоками, разбор записей параллельно, сборка путей по parent-id без рекурсии; fixup-проверка обязательна.
3. **Агрегация:** один обратный проход по arena (уже так).
4. **Treemap:** раскладка ограничена глубиной по минимальному размеру прямоугольника (< 1–2 пикселя не раскладываем), кэш по (ревизия, размер, фокус), рендер — единый mesh/текстура с cushion-шейдингом, пересборка только при смене кэша.
5. **Список/дерево UI:** виртуализация строк (рисуем только видимые), сортировка в фоне.
6. **Память:** интернирование расширений, имена как `Box<str>`; кластеры — в `u32`-единицах там, где это экономит место.

## Анти-паттерны

Сканирование/агрегация/раскладка в UI-потоке; клонирование дерева на кадр; `String` на каждый узел для пути (путь собирается по требованию); сортировка всего дерева ради топ-N (используй частичный выбор).
